## 윈도우 서비스 개요

# 서비스(Service)

- 서비스(Service): 사용자와 직접 상호작용하지 않고 백그라운드에서 실행되면서 특정 기능을 지속적으로 제공하는 프로그램
- Windows가 시작될 때 자동으로 실행되도록 설정할 수 있으며, 사용자가 로그인하지 않은 상태에서도 실행될 수 있다.
- 일반적인 응용 프로그램과 달리 사용자의 직접적인 조작 없이 시스템의 기능이나 네트워크 기능 등을 제공하는 것이 주요 목적이다.
- Windows 서비스는 **Service Control Manager(SCM)**에 의해 생성, 시작, 중지 및 관리된다.
- Unix/Linux의 **데몬(Daemon)**과 개념적으로 유사하다.

### 서비스의 특징

- 백그라운드에서 실행
- 사용자의 직접적인 개입 없이 동작 가능
- 시스템 부팅 시 자동 실행 가능
- 서비스 시작/중지/일시 중지 등의 상태를 가질 수 있음
- 특정 사용자 계정 또는 시스템 계정의 권한으로 실행
- 다른 서비스나 시스템 구성요소와 의존 관계를 가질 수 있음

### 서비스의 실행 상태

Windows 서비스는 일반적으로 다음과 같은 상태를 가질 수 있다.

- 실행 중(Running)
- 중지됨(Stopped)
- 시작 중(Start Pending)
- 중지 중(Stop Pending)
- 일시 중지됨(Paused)
- 일시 중지 중(Pause Pending)
- 다시 시작 중(Continue Pending)

# 서비스 실행 계정

Windows 서비스는 특정 계정의 권한으로 실행된다.

대표적인 기본 서비스 계정은 다음과 같다.

## 1) Local System

- 매우 높은 수준의 로컬 시스템 권한을 가진 계정
- 로컬 컴퓨터의 시스템 리소스에 강한 권한을 가진다.
- 네트워크상의 다른 컴퓨터에 접근할 때는 일반적으로 컴퓨터 계정의 자격 증명을 사용한다.
- 강력한 권한이 필요한 시스템 서비스에서 사용될 수 있다.

```text
Local System
→ 로컬 시스템에서 매우 높은 권한
→ 일반 사용자보다 훨씬 강한 권한
```

## 2) Local Service

- 로컬 컴퓨터에서 제한된 권한으로 서비스를 실행하기 위한 기본 제공 계정
- Local System보다 권한이 낮다.
- 네트워크에 접근할 때는 일반적으로 익명 자격 증명을 사용한다.
- 서비스가 높은 권한을 필요로 하지 않는 경우 보안 강화를 위해 사용할 수 있다.

## 3) Network Service

- 로컬 컴퓨터에서는 제한된 권한으로 실행된다.
- 네트워크 리소스에 접근할 때 컴퓨터 계정의 자격 증명을 사용할 수 있다.
- 네트워크를 사용하는 서비스에서 활용될 수 있다.

### 서비스 계정 비교

| 계정 | 로컬 권한 | 네트워크 접근 특징 |
|---|---|---|
| Local System | 매우 높음 | 컴퓨터 계정 사용 가능 |
| Local Service | 낮음 | 일반적으로 익명 |
| Network Service | 낮음 | 컴퓨터 계정 사용 가능 |

> 서비스에 불필요하게 높은 권한을 부여하면 보안 위험이 증가할 수 있으므로 필요한 최소 권한으로 실행하는 것이 좋다.

# 서비스 조회 방법

## 1) 작업 관리자(Task Manager)

- 작업 관리자에서 실행 중인 프로세스와 연결된 서비스 정보를 확인할 수 있다.
- Windows에서는 서비스 탭을 통해 실행 중인 서비스의 상태를 확인할 수 있다.
- 특정 서비스와 어떤 프로세스가 연결되어 있는지 확인할 때 유용하다.

```text
작업 관리자
→ 서비스
→ 서비스 이름 / PID / 상태 확인
```

---

## 2) CMD

### net start

```cmd
net start
```

- 현재 실행 중인 Windows 서비스 목록을 확인한다.

특정 서비스를 시작할 수도 있다.

```cmd
net start 서비스이름
```

서비스 중지:

```cmd
net stop 서비스이름
```

> `net start`는 기본적으로 실행 중인 서비스 목록을 보여주며, 모든 서비스의 상세한 설정 정보를 확인하는 용도는 아니다.

---

### sc query

```cmd
sc query
```

- Windows 서비스의 상태 정보를 확인한다.
- 서비스 이름, 상태, 상태 코드 등의 정보를 확인할 수 있다.

특정 서비스를 조회:

```cmd
sc query 서비스이름
```

서비스의 상세 설정 정보를 확인:

```cmd
sc qc 서비스이름
```

예:

```cmd
sc query w32time
sc qc w32time
```

- `sc query`
  - 서비스의 현재 상태 확인

- `sc qc`
  - 서비스의 구성(Configuration) 정보 확인
  - 실행 파일 경로
  - 시작 유형
  - 서비스 계정
  - 의존 서비스 등의 정보 확인

---

## 3) services.msc

```cmd
services.msc
```

- Windows의 서비스 관리 콘솔을 실행한다.
- GUI 환경에서 서비스를 확인하고 관리할 수 있다.

### 확인 가능한 정보

- 서비스 이름
- 표시 이름
- 상태
- 시작 유형
- 로그온 계정
- 서비스 설명
- 종속성

### 시작 유형

- 자동(Automatic)
  - Windows가 시작될 때 자동으로 서비스를 시작한다.

- 자동(지연된 시작)(Automatic Delayed Start)
  - 시스템 시작 과정에서 일정 시간이 지난 후 서비스를 시작한다.

- 수동(Manual)
  - 필요한 경우 다른 구성요소에 의해 시작될 수 있다.

- 사용 안 함(Disabled)
  - 서비스가 시작되지 않도록 설정한다.

# 주요 Windows 서비스

## 1) Windows Event Log

- Windows 이벤트 로그를 관리하는 핵심 서비스
- 운영체제, 시스템 구성요소 및 응용 프로그램에서 발생하는 다양한 이벤트를 기록하고 관리한다.
- 이벤트 뷰어(Event Viewer)를 통해 기록된 이벤트를 확인할 수 있다.

### 주요 용도

- 시스템 오류 확인
- 서비스 오류 확인
- 로그인 및 보안 관련 이벤트 확인
- 응용 프로그램 오류 확인
- 장애 원인 분석
- 보안 이벤트 분석

```text
프로그램 / Windows 구성요소
          ↓
      이벤트 발생
          ↓
Windows Event Log
          ↓
      이벤트 로그
          ↓
   이벤트 뷰어(Event Viewer)
```

---

## 2) Network Connections

- **Network Connections** 서비스
- 네트워크 및 원격 액세스 연결과 관련된 객체를 관리하는 기능을 제공한다.
- 네트워크 연결 상태 및 구성과 관련된 기능에 관여한다.
- 이 서비스를 중지하면 네트워크 구성 및 연결 관리에 영향을 줄 수 있다.

> "서비스를 중지하면 모든 네트워크 접속이 불가능하다"고 단정하는 것은 정확하지 않다.
> 이미 설정되어 있는 네트워크 연결이 즉시 모두 끊어진다고 단순하게 이해하기보다는, 네트워크 연결 관리 및 구성 기능에 영향을 줄 수 있다고 이해하는 것이 좋다.

---

## 3) Shell Hardware Detection

- **Shell Hardware Detection**
- 이동식 저장 장치나 기타 하드웨어 장치가 연결되었을 때 Windows 셸이 해당 장치를 인식하고 관련 동작을 수행하도록 지원한다.
- AutoPlay와 같은 기능과 관련되어 있다.

### 예

```text
USB 메모리 연결
      ↓
Windows에서 장치 인식
      ↓
Shell Hardware Detection
      ↓
AutoPlay 등의 관련 기능 동작
```

---

## 4) Plug and Play

- **Plug and Play(PnP)**
- 새로운 하드웨어 장치를 자동으로 인식하고 운영체제가 사용할 수 있도록 구성하는 기능
- 하드웨어 장치와 장치 드라이버의 인식 및 구성을 지원한다.

### 주요 기능

- 하드웨어 장치 검색
- 장치 드라이버 로드
- 하드웨어 리소스 구성
- 장치 추가 및 제거 관리

> PnP는 단순히 하나의 서비스만을 의미하는 것이 아니라 Windows 운영체제의 전반적인 **Plug and Play 기능 및 구성요소**를 의미한다.
> 따라서 PnP 기능을 서비스 하나로만 이해하는 것은 적절하지 않다.

---

## 5) Server

- **Server(LanmanServer)**
- Windows 컴퓨터가 네트워크를 통해 파일, 프린터 및 기타 리소스를 공유할 수 있도록 지원한다.
- SMB(Server Message Block) 기반의 네트워크 공유 기능에 사용된다.
- 서버 역할을 수행하는 Windows 컴퓨터에서 중요한 서비스이다.

### 예

```text
클라이언트 PC
      ↓
     SMB
      ↓
Server 서비스
      ↓
공유 폴더 / 공유 프린터
```

> Server 서비스와 RPC는 서로 다른 기능이다.
> Server 서비스가 RPC 자체를 제공하는 것으로 이해해서는 안 된다.

---

## 6) Workstation

- **Workstation(LanmanWorkstation)**
- Windows 컴퓨터가 SMB 기반 네트워크 리소스에 클라이언트로 접근할 수 있도록 지원한다.
- 네트워크 공유 폴더, 파일 및 프린터 등의 접근과 관련된 기능을 제공한다.

### Server와 Workstation의 차이

```text
Server
→ 내 컴퓨터의 리소스를 다른 컴퓨터에 제공

Workstation
→ 다른 컴퓨터의 네트워크 리소스에 접근
```

예:

```text
PC A                         PC B
(Server)                     (Workstation)
공유 폴더 제공  ←── SMB ──→  공유 폴더 접근
```

---

## 7) DHCP Client

- **DHCP Client**
- DHCP 서버로부터 IP 주소 및 네트워크 구성 정보를 동적으로 할당받는다.
- DHCP를 사용하는 클라이언트 컴퓨터에서 중요한 서비스이다.

### DHCP를 통해 얻을 수 있는 정보

- IP 주소
- 서브넷 마스크
- 기본 게이트웨이
- DNS 서버 주소
- 임대 시간 등의 네트워크 구성 정보

```text
DHCP Client
     ↓
DHCP Discover
     ↓
DHCP Server
     ↓
IP 주소 및 네트워크 정보 할당
```

> "IP 주소와 DNS 이름을 DHCP 서버에 등록한다"는 내용은 DHCP 자체의 기본 역할이라기보다는 **DHCP와 DNS의 연동 환경에서 발생할 수 있는 기능**이다.

---

## 8) Security Accounts Manager(SAM)

- **Security Accounts Manager(SAM)**
- Windows 로컬 사용자 계정 및 그룹 계정 정보를 저장하고 관리하는 보안 구성요소
- 로컬 계정의 인증 과정에 사용되는 정보를 관리한다.
- SAM 데이터베이스는 일반적으로 다음 위치에 존재한다.

```text
C:\Windows\System32\config\SAM
```

> SAM은 단순히 "계정 인증 서비스"라고만 이해하기보다는 **로컬 사용자 및 그룹 계정 정보를 저장하고 관리하는 구성요소**로 이해하는 것이 정확하다.
> 인증 과정에는 LSASS 등의 다른 보안 구성요소도 함께 관여한다.

---

## 9) Windows Management Instrumentation(WMI)

- **WMI(Windows Management Instrumentation)**
- Windows 시스템의 관리 및 모니터링 정보를 제공하기 위한 관리 기술
- 운영체제, 하드웨어, 응용 프로그램 등의 정보를 조회하고 관리할 수 있도록 인터페이스를 제공한다.
- 시스템 관리자 및 관리 프로그램이 Windows 시스템 정보를 확인하고 관리할 때 사용된다.

### WMI를 이용한 정보 조회 예

- CPU 정보
- 메모리 정보
- 디스크 정보
- 프로세스 정보
- 서비스 정보
- 네트워크 구성 정보
- 이벤트 및 시스템 관리 정보

```text
관리 프로그램
      ↓
     WMI
      ↓
Windows 관리 정보
      ↓
CPU / 메모리 / 프로세스 / 서비스 등
```

> WMI는 단순히 "응용 프로그램과 서비스가 생성하는 관리 이벤트에 접근하는 서비스"가 아니다.
> Windows 시스템 전반의 관리 정보를 조회하고 관리할 수 있도록 하는 **관리 인프라 및 기술**이다.

---

## 10) Windows Management Instrumentation Driver Extensions

- **Windows Management Instrumentation Driver Extensions**
- WMI 정보를 제공하는 장치 드라이버와 WMI 간의 연동을 지원하는 구성요소
- WMI를 통해 장치 드라이버의 관리 정보를 조회하거나 이벤트를 전달하는 데 사용된다.
- 일반적인 Windows 서비스처럼 직접 사용하는 기능이라기보다는 **WMI와 장치 드라이버 사이의 관리 정보 연동**과 관련된 구성요소로 이해하는 것이 좋다.

---

## 11) Application Management

- **Application Management(AppMgmt)**
- Windows에서 MSI 기반 응용 프로그램의 설치, 수정, 제거와 관련된 기능을 지원한다.
- 그룹 정책 등을 통한 소프트웨어 배포 환경에서도 사용될 수 있다.

> 이 서비스를 중지한다고 해서 Windows에서 모든 프로그램의 설치 및 제거가 불가능해지는 것은 아니다.
> 특히 모든 설치 프로그램이 이 서비스를 사용하는 것은 아니며, MSI 기반 설치 및 관련 관리 기능에 영향을 줄 수 있다.

---

## 12) Remote Procedure Call(RPC)

- **Remote Procedure Call(RPC)**
- 다른 프로세스 또는 다른 컴퓨터에서 실행되는 프로그램의 기능을 호출할 수 있도록 지원하는 통신 기술
- Windows의 다양한 시스템 구성요소와 서비스가 서로 통신하는 데 사용된다.
- Windows에서는 RPC를 기반으로 동작하는 기능이 많기 때문에 매우 중요한 시스템 서비스이다.

### RPC의 기본 개념

```text
프로세스 A
   ↓
RPC 요청
   ↓
프로세스 B
   ↓
요청한 작업 수행
   ↓
결과 반환
```

- 이름에 "Remote"가 포함되어 있지만 반드시 다른 컴퓨터와의 통신만을 의미하는 것은 아니다.
- 동일한 컴퓨터의 서로 다른 프로세스 간 통신에서도 RPC 메커니즘이 사용될 수 있다.

> RPC 서비스를 중지하면 RPC에 의존하는 많은 Windows 서비스와 기능이 정상적으로 동작하지 않을 수 있다.
> 그러나 "RPC를 중단하면 반드시 블루스크린이 발생한다"고 단정하는 것은 부정확하다.
> 시스템 구성과 Windows 버전에 따라 다양한 서비스와 기능이 영향을 받을 수 있다.

# 서비스와 프로세스의 관계

Windows 서비스와 프로세스는 동일한 개념이 아니다.

```text
서비스
→ 백그라운드에서 특정 기능을 제공하는 관리 단위

프로세스
→ 실제 실행되고 있는 프로그램의 인스턴스
```

하나의 서비스는 특정 프로세스에서 실행될 수 있다.

```text
Windows Service
      ↓
서비스 실행
      ↓
프로세스
      ↓
스레드
```

또한 여러 서비스가 하나의 프로세스에 포함될 수도 있다.

대표적인 예가 `svchost.exe`이다.

```text
services.exe
      │
      ├── svchost.exe
      │      ├── Service A
      │      └── Service B
      │
      └── svchost.exe
             ├── Service C
             └── Service D
```

# 서비스 장애 및 분석

특정 서비스에서 문제가 발생했을 때는 단순히 서비스를 재시작하는 것보다 다음과 같은 정보를 확인하는 것이 좋다.

### 1) 서비스 상태 확인

```cmd
sc query 서비스이름
```

### 2) 서비스 설정 확인

```cmd
sc qc 서비스이름
```

### 3) 서비스가 사용하는 프로세스 확인

- 작업 관리자
- `tasklist /svc`
- Process Explorer 등의 도구를 이용할 수 있다.

```cmd
tasklist /svc
```

### 4) 이벤트 로그 확인

- 이벤트 뷰어에서 시스템 및 응용 프로그램 로그를 확인한다.

```text
이벤트 뷰어
→ Windows 로그
→ 시스템
→ 응용 프로그램
```

### 5) 서비스 의존성 확인

```cmd
sc qc 서비스이름
```

- 특정 서비스가 다른 서비스에 의존하고 있는지 확인한다.
- 의존 서비스에 장애가 발생하면 해당 서비스도 정상적으로 시작되지 않을 수 있다.

# 주요 서비스 정리

| 서비스 | 주요 역할 |
|---|---|
| Windows Event Log | Windows 및 응용 프로그램의 이벤트 로그 관리 |
| Network Connections | 네트워크 연결 및 구성 관리 관련 기능 |
| Shell Hardware Detection | AutoPlay 및 하드웨어 이벤트 처리 지원 |
| Plug and Play | 하드웨어 인식 및 구성 |
| Server | SMB 기반 파일 및 프린터 공유 제공 |
| Workstation | SMB 기반 네트워크 리소스 접근 |
| DHCP Client | DHCP를 통한 네트워크 구성 정보 획득 |
| Security Accounts Manager | 로컬 사용자 및 그룹 계정 정보 관리 |
| WMI | Windows 시스템 관리 정보 제공 |
| WMI Driver Extensions | WMI와 장치 드라이버의 관리 정보 연동 |
| Application Management | MSI 기반 응용 프로그램 관리 지원 |
| RPC | 프로세스 및 시스템 구성요소 간 RPC 통신 지원 |

# 핵심 정리

```text
Windows Service
→ 백그라운드에서 특정 기능을 지속적으로 제공
→ Service Control Manager(SCM)가 관리
→ 시스템 부팅 시 자동 실행 가능
→ 사용자 로그인 없이도 실행 가능

주요 실행 계정
→ Local System
→ Local Service
→ Network Service

서비스 확인
→ 작업 관리자
→ services.msc
→ net start
→ sc query
→ sc qc

서비스 문제 분석
→ 서비스 상태 확인
→ 서비스 구성 확인
→ 실행 프로세스 확인
→ 이벤트 로그 확인
→ 의존성 확인
```

### 서비스와 프로세스의 관계

```text
서비스
   ↓
Service Control Manager
   ↓
서비스 실행
   ↓
프로세스
   ↓
스레드
```

### 보안 관점

```text
의심스러운 서비스 발견
        ↓
서비스 이름 확인
        ↓
실행 파일 경로 확인
        ↓
실행 계정 확인
        ↓
부모 프로세스 및 프로세스 확인
        ↓
디지털 서명 확인
        ↓
네트워크 통신 확인
        ↓
이벤트 로그 확인
```

- 악성 프로그램은 정상적인 Windows 서비스와 유사한 이름으로 서비스를 등록할 수 있다.
- 따라서 서비스 이름만 확인하지 말고 **실행 파일 경로, 실행 계정, 시작 유형, 프로세스, 디지털 서명, 네트워크 연결** 등을 함께 확인해야 한다.
