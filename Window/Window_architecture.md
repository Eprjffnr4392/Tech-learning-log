# 윈도우 아키텍처

- 윈도우는 크게 유저 모드(User Mode)와 커널 모드(Kernel Mode)로 구분된다.
- 유저 모드와 커널 모드는 서로 다른 권한 수준에서 실행되며, 시스템의 안정성과 보안을 유지하기 위해 분리되어 있다.
- 일반적인 응용 프로그램은 유저 모드에서 실행되며, 운영체제의 핵심 기능과 하드웨어에 직접 접근할 필요가 있는 작업은 커널 모드에서 수행된다.
- 이러한 계층적인 구조를 통해 응용 프로그램의 오류가 운영체제 전체에 직접적인 영향을 주는 것을 방지한다.
- 윈도우 NT 아키텍처는 운영체제의 기능을 여러 구성요소로 분리하여 모듈화한 구조를 사용한다.

## 윈도우 NT 아키텍처

- Windows NT 계열 운영체제는 크게 유저 모드(User Mode)와 커널 모드(Kernel Mode)로 구성된다.
- 각 모드는 서로 다른 권한 수준에서 실행된다.

### 유저 모드(User Mode)

- 일반적인 사용자 응용 프로그램과 일부 시스템 서비스가 실행되는 영역
- 시스템 데이터와 하드웨어에 대한 직접적인 접근이 제한된다.
- 응용 프로그램이 잘못 동작하더라도 다른 프로세스나 운영체제의 핵심 영역에 직접적인 영향을 주지 않도록 보호된다.
- 하드웨어에 직접 접근해야 하는 경우 시스템 호출(System Call)을 통해 커널 모드의 기능을 요청한다.

### 커널 모드(Kernel Mode)

- 운영체제의 핵심 구성요소와 장치 드라이버 등이 실행되는 영역
- 시스템 메모리와 하드웨어 등의 시스템 자원에 높은 권한으로 접근할 수 있다.
- 프로세스 및 스레드 관리
- 메모리 관리
- 입출력 관리
- 하드웨어 제어
- 보안 관리
- 시스템 호출 처리 등의 역할을 수행한다.

# 유저 모드

## 환경 서브시스템(Environment Subsystems)

- 응용 프로그램이 특정 운영체제 환경의 API를 사용할 수 있도록 지원하는 구성요소
- 초기 Windows NT에서는 여러 운영체제 환경과의 호환성을 고려하여 Win32, OS/2, POSIX 등의 서브시스템이 존재했다.
- 현재 Windows에서는 **Win32 서브시스템이 핵심적인 사용자 환경**을 담당한다.
- OS/2 및 POSIX 서브시스템은 현재의 Windows에서는 기본 구성요소가 아니다.

### Win32 서브시스템

- Windows 응용 프로그램이 Windows API를 사용할 수 있도록 지원한다.
- 프로세스 및 스레드 생성, 파일 입출력, 메모리 관리, GUI 등의 기능을 제공한다.

---

## 시스템 서비스 및 서브시스템

- Windows에는 운영체제의 기능을 제공하는 다양한 시스템 프로세스와 서비스가 존재한다.
- 과거 Windows NT 아키텍처 설명에서는 환경 서브시스템(Environment Subsystems)과 **보호된 서브시스템(Protected Subsystems)** 등의 개념으로 설명하기도 한다.
- 보안, 네트워크, 로그인 등의 기능은 여러 시스템 프로세스와 서비스가 분담하여 수행한다.

### 보안 관련 기능

- 사용자 계정 및 권한 관리
- 사용자 인증
- 보안 토큰 관리
- 접근 제어

### Workstation 서비스

- Windows 클라이언트가 네트워크의 다른 컴퓨터 또는 서버에 접근할 수 있도록 지원한다.
- SMB(Server Message Block) 기반 네트워크 기능 등을 지원한다.

### Server 서비스

- Windows 컴퓨터가 네트워크를 통해 파일이나 프린터 등의 리소스를 제공할 수 있도록 지원한다.
- SMB 기반의 파일 및 프린터 공유 등에 사용된다.

# 커널 모드

Windows 커널 모드는 일반적으로 다음과 같은 주요 구성요소로 구분할 수 있다.

- Executive
- Windows Kernel
- Device Drivers
- Hardware Abstraction Layer(HAL)

---

## Executive

- 운영체제의 주요 시스템 서비스를 제공하는 커널 모드 구성요소
- 프로세스, 메모리, I/O, 보안, Plug and Play, 전원 관리 등의 기능을 담당한다.

### I/O Manager

- 시스템의 입출력(I/O)을 관리한다.
- 응용 프로그램의 I/O 요청을 커널 모드의 장치 드라이버로 전달한다.
- 파일, 네트워크, 저장 장치 등의 I/O 작업을 관리한다.
- 응용 프로그램이 하드웨어에 직접 접근하는 것이 아니라 운영체제의 I/O 시스템과 장치 드라이버를 통해 접근하도록 한다.

### Security Reference Monitor(SRM)

- 시스템의 보안 정책과 접근 제어를 적용한다.
- 객체에 대한 접근 권한을 검사한다.
- 사용자의 보안 토큰(Security Token)을 기반으로 리소스 접근 여부를 판단한다.
- 파일, 레지스트리, 프로세스 등의 시스템 객체에 대한 접근 제어에 관여한다.

### Process Manager

- 프로세스와 스레드의 생성 및 종료와 관련된 기능을 관리한다.
- 프로세스와 스레드의 실행에 필요한 정보를 관리한다.

### Virtual Memory Manager

- 가상 메모리를 관리한다.
- 프로세스가 사용하는 가상 주소 공간을 관리한다.
- 물리 메모리와 가상 메모리의 매핑을 관리한다.
- 페이징 등의 메모리 관리 기능을 수행한다.

### Plug and Play Manager

- Plug and Play(PnP) 기능을 관리한다.
- 하드웨어 장치의 검색 및 인식
- 장치 드라이버 로드 및 관리
- 장치의 리소스 할당 등의 작업을 수행한다.

### Power Manager

- 시스템의 전원 상태와 관련된 기능을 관리한다.
- 절전 모드, 최대 절전 모드, 시스템 종료 및 전원 상태 변경 등의 작업에 관여한다.

> 참고: IPC(Inter-Process Communication)는 Windows의 여러 구성요소가 프로세스 간 통신을 수행하는 개념이며, Windows NT의 Executive 내부에 독립적인 "IPC Manager"라는 구성요소가 존재하여 모든 IPC를 담당한다고 보는 것은 정확하지 않다.
> Windows에서는 LPC(Local Procedure Call), ALPC(Advanced Local Procedure Call), RPC(Remote Procedure Call) 등 다양한 IPC 메커니즘이 사용된다.

# Windows Kernel

- Windows 운영체제의 핵심 커널 구성요소
- 스레드 스케줄링
- 인터럽트 및 예외 처리
- 동기화
- 저수준 프로세서 관리 등의 기능을 담당한다.
- Executive에서 제공하는 시스템 서비스가 실행될 수 있도록 기본적인 커널 기능을 제공한다.

# Windows 그래픽 시스템

## Window Manager

- Windows의 GUI 환경에서 창(Window), 입력, 화면 구성 등의 관리를 담당하는 구성요소
- 현대 Windows에서는 그래픽 시스템이 여러 구성요소로 나뉘어 동작한다.
- 단순히 "화면에 창을 그리는 역할만 수행한다"고 이해하기보다는 GUI와 창 관리 기능을 담당한다고 이해하는 것이 적절하다.

## GDI(Graphics Device Interface)

- Windows의 2차원 그래픽 기능을 제공하는 구성요소
- 응용 프로그램이 특정 하드웨어의 세부적인 동작을 직접 알지 않아도 그래픽을 출력할 수 있도록 추상화된 인터페이스를 제공한다.
- 주요 기능
  - 문자 및 폰트 출력
  - 선과 곡선 등의 도형 출력
  - 비트맵 처리
  - 그래픽 객체 관리
  - 프린터 출력

> 참고: GDI와 Window Manager는 Windows 그래픽 시스템의 구성요소이며, 단순히 Executive 내부의 동일한 하위 구성요소로 묶어서 이해하지 않는 것이 좋다.

# 마이크로커널(Microkernel)

- Windows NT는 마이크로커널의 개념을 기반으로 설계되었지만, 현재의 Windows NT 계열은 전통적인 의미의 순수 마이크로커널 구조가 아니다.
- 초기 Windows NT에서는 커널의 핵심 기능을 최소화하고 나머지 운영체제 기능을 분리하는 마이크로커널 설계 철학을 적용했다.
- 현재 Windows NT는 일반적으로 **하이브리드 커널(Hybrid Kernel)** 구조로 설명된다.

### 커널의 주요 역할

- 스레드 스케줄링
- 인터럽트 및 예외 처리
- 프로세서 관리
- 저수준 동기화
- 하드웨어와 운영체제 구성요소 사이의 기본적인 인터페이스 제공

> 마이크로커널 또는 커널은 운영체제의 핵심 기능을 담당하지만, Windows의 재부팅이나 공장 초기화가 마이크로커널과 직접적인 연관이 있기 때문이라고 설명하는 것은 부정확하다.
> 재부팅은 운영체제의 전원 관리 및 시스템 종료 기능과 관련되고, 공장 초기화는 운영체제 복구 및 시스템 복원 기능과 관련된다.

# 커널 모드 드라이버

- 하드웨어 장치와 운영체제 사이에서 동작하는 소프트웨어
- 운영체제가 다양한 하드웨어 장치를 사용할 수 있도록 인터페이스를 제공한다.
- I/O Manager 등의 커널 구성요소와 연동하여 장치의 입출력을 처리한다.

### 드라이버의 역할

- 하드웨어 장치 초기화
- 장치에 대한 입출력 요청 처리
- 운영체제의 요청을 하드웨어가 이해할 수 있는 명령으로 변환
- 장치 상태 및 오류 관리

### 드라이버의 계층

- Windows의 일부 장치 드라이버 구조에서는 여러 계층의 드라이버가 스택 형태로 구성될 수 있다.
- 일반적으로 다음과 같이 설명할 수 있다.

```text
응용 프로그램
      ↓
I/O Manager
      ↓
상위 수준 드라이버
      ↓
중간 수준 드라이버
      ↓
하위 수준 드라이버
      ↓
하드웨어 장치
```

- 모든 장치 드라이버가 반드시 위와 같은 세 단계로 구성되는 것은 아니며, 장치 종류와 드라이버 구조에 따라 달라질 수 있다.

# Hardware Abstraction Layer(HAL)

- HAL(Hardware Abstraction Layer)
- 물리적인 하드웨어와 Windows의 나머지 구성요소 사이에서 하드웨어의 차이를 추상화하는 계층
- CPU, 인터럽트 컨트롤러, DMA, 타이머 등의 하드웨어 차이를 운영체제의 상위 구성요소가 직접 처리하지 않도록 추상화한다.
- 동일한 운영체제가 다양한 하드웨어 플랫폼에서 동작할 수 있도록 지원한다.

### HAL의 목적

```text
Windows 운영체제
       ↓
      HAL
       ↓
물리적 하드웨어
```

- 하드웨어의 세부적인 차이를 HAL이 추상화하여 운영체제의 다른 구성요소가 하드웨어에 종속되는 것을 줄인다.
- 따라서 운영체제의 이식성과 하드웨어 호환성을 높이는 데 도움을 준다.

```text

│          User Mode                  │
│                                     │

│                                     │
└─────────────────────────────────────┘
                 │
          System Call / API
                 ↓
┌─────────────────────────────────────┐
│          Kernel Mode                │
│                                     │
│  Executive                          │
│  ├─ I/O Manager                     │
│  ├─ Process Manager                 │
│  ├─ Virtual Memory Manager          │
│  ├─ Security Reference Monitor      │
│  ├─ PnP Manager                     │
│  └─ Power Manager                   │
│                                     │
│  Windows Kernel                     │
│  ├─ 스케줄링                         │
│  ├─ 인터럽트/예외 처리              │
│  └─ 동기화                           │
│                                     │

│                                     │

│                                     │

                 │
                 ↓

```

# 정리

- Windows NT 계열은 크게 **유저 모드와 커널 모드**로 구분된다.

### 유저 모드

- 일반 응용 프로그램 실행
- 시스템 자원에 대한 직접 접근 제한
- 시스템 호출을 통해 커널 모드 기능 요청

### 커널 모드

- 운영체제 핵심 기능 수행
- 높은 권한으로 시스템 자원 및 하드웨어 접근
- 프로세스 및 스레드 관리
- 메모리 관리
- 입출력 관리
- 보안 관리
- 장치 관리

### 주요 커널 모드 구성요소

- Executive
  - I/O Manager
  - Process Manager
  - Virtual Memory Manager
  - Security Reference Monitor
  - Plug and Play Manager
  - Power Manager

- Windows Kernel
  - 스케줄링
  - 인터럽트 및 예외 처리
  - 동기화

- Device Drivers
  - 운영체제와 하드웨어 사이의 인터페이스 제공

- HAL
  - 하드웨어의 차이를 추상화하여 운영체제에 일관된 인터페이스 제공

### 핵심 개념

```text
유저 모드
→ 응용 프로그램이 실행되는 영역
→ 권한 제한

        ↓ System Call

커널 모드
→ 운영체제 핵심 기능이 실행되는 영역
→ 높은 권한

        ↓

HAL / Device Driver
→ 하드웨어의 차이를 추상화하고 하드웨어와 통신

        ↓

물리적 하드웨어
```
