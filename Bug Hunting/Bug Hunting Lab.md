# 1. 버그헌팅과 자동화 도구

## 1.1. 버그헌팅과 자동화 도구의 필요성

● **효율성 증대:** 버그헌팅은 많은 시간과 반복 작업이 필요한 작업이다. 대상 시스템을 체계적으로 탐색하거나 반복적인 테스트를 수행할 때 자동화 도구를 활용하면 작업 효율을 크게 높일 수 있다.

● **역할:** 자동화 도구는 해커를 대신하여 모든 취약점을 찾아주는 도구가 아니라, 해커가 자신의 작업을 더 효율적으로 수행할 수 있도록 돕는 도구이다.

---

## 1.2. SQLMap: SQL Injection 자동화 도구

● **개요:** SQLMap은 MySQL, Oracle, MSSQL 등 다양한 DBMS를 지원하는 오픈소스 SQL Injection 자동화 도구이다.

● **주요 옵션:**

○ `--delay`: 요청 또는 쿼리 실행 사이의 지연 시간을 설정하여 서버에 가해지는 부하를 줄이는 데 사용할 수 있다.

○ `--risk`: 테스트 과정에서 수행할 수 있는 요청의 위험 수준을 조절한다. 운영 환경에서는 서비스에 영향을 줄 수 있는 테스트를 신중하게 수행해야 한다.

○ `--tor`: Tor 네트워크를 통해 요청을 전달하는 옵션이다. 허가된 테스트 환경에서 네트워크 경로를 변경할 필요가 있을 때 사용할 수 있다.

○ `-r`: 캡처한 HTTP 요청 파일을 불러와 SQL Injection 테스트에 활용한다. 복잡한 헤더나 요청 데이터를 직접 입력할 필요가 없어 유용하다.

● **주요 기능:**

○ `--file-read`: SQL Injection을 통해 서버의 파일을 읽을 수 있는 환경에서 파일 읽기를 시도하는 기능이다.

○ `--os-shell`: 특정 조건에서 데이터베이스 서버의 운영체제 명령 실행을 시도하는 기능이다.

● **주의사항 (Expert Tip):**

SQLMap과 같은 자동화 도구는 애플리케이션의 비즈니스 로직을 완전히 이해하지 못한다.

따라서 먼저 수동으로 취약점과 영향을 확인한 후, 필요한 경우 자동화 도구를 활용하여 추가적인 검증을 수행하는 것이 좋다.

## 1.3. JWT (JSON Web Token) 크래킹

● **JWT 구조:** JWT는 일반적으로 다음과 같은 세 부분으로 구성된다.

`Header.Payload.Signature`

Header와 Payload는 Base64URL 방식으로 인코딩되어 있으므로 누구나 내용을 확인할 수 있다. 따라서 JWT Payload에 비밀번호 등의 민감한 정보를 저장해서는 안 된다.

JWT의 무결성은 Signature를 통해 검증한다.

● **취약점:** JWT 자체가 취약한 것이 아니라, 서명에 사용되는 비밀키(Secret Key)가 지나치게 단순하거나 노출된 경우 문제가 발생할 수 있다.

비밀키가 충분히 강하지 않으면 사전 대입이나 무차별 대입 등의 공격을 통해 키를 추측할 가능성이 있다.

● **공격 도구 및 원리:**

○ `jwt_tool`, `jwtcrack` 등의 도구를 이용하여 JWT의 구조와 서명을 분석할 수 있다.

○ 서명 검증에 사용되는 비밀키를 확보하면 공격자가 임의의 Payload를 가진 토큰을 생성할 가능성이 있다.

○ 서버가 해당 토큰을 정상적인 토큰으로 신뢰한다면 권한 상승이나 계정 탈취 등의 문제로 이어질 수 있다.

## 1.4. Hashcat: 패스워드 복구 도구

● **개요:** Hashcat은 해시된 패스워드의 원본 값을 추측하는 패스워드 복구 및 크래킹 도구이다.

침투 테스트에서는 허가된 환경에서 획득한 패스워드 해시의 강도를 평가하거나, 비밀번호 정책의 취약성을 확인하는 데 활용할 수 있다.

● **해시 식별:** 해시의 종류를 알 수 없는 경우 CyberChef의 `Hash Analyzer` 등의 도구를 활용하여 MD5, SHA-1 등의 해시 형식을 추정할 수 있다.

● **공격 모드 (Attack Modes):**

1. **사전 공격 (Dictionary Attack):**  
   미리 준비된 단어 목록을 이용하여 패스워드를 대입한다.

2. **조합 공격 (Combinator Attack):**  
   두 개 이상의 단어 목록을 조합하여 패스워드를 추측한다.

3. **마스크 공격 (Mask Attack):**  
   패스워드의 일정한 패턴을 알고 있을 때 해당 패턴을 기반으로 후보 값을 생성하여 대입한다.  
   예: `Pass + 숫자 4자리`

4. **규칙 기반 공격 (Rule-based Attack):**  
   기존 단어에 대소문자 변경, 숫자 또는 특수문자 추가 등의 규칙을 적용하여 다양한 패스워드 후보를 생성한다.

## 1.5. 핵심내용 (Summary)

1. **SQLMap 활용:**  
   `-r`을 이용한 요청 파일 로드, `--delay`를 이용한 요청 간 지연, `--risk`를 이용한 위험 수준 조절 등은 SQL Injection 테스트에서 유용한 기능이다. 자동화된 공격 기능은 반드시 허가된 환경에서 사용해야 하며, 수동 검증을 먼저 수행하는 것이 중요하다.

2. **JWT의 약점:**  
   JWT 자체가 안전하지 않은 것이 아니라, 약한 비밀키나 잘못된 서명 검증 등의 구현 문제가 보안 취약점으로 이어질 수 있다.

3. **Hashcat의 활용:**  
   해시값을 확보했다고 해서 패스워드가 즉시 노출되는 것은 아니지만, 약한 패스워드는 사전 공격이나 마스크 공격 등을 통해 추측될 가능성이 있다.

4. **도구의 한계:**  
   자동화 도구는 애플리케이션의 비즈니스 로직과 전체적인 데이터 흐름을 이해하지 못한다. 따라서 도구에만 의존하면 복잡한 취약점을 놓치거나 대상 시스템에 불필요한 부하를 줄 수 있다.

5. **권장 프로세스:**  
   **수동 분석 → 취약점 확인 → 자동화 도구를 이용한 검증 → 영향도 분석**의 순서로 접근하는 것이 효율적이다.
