# 11. Linux 계정 관리

## 11.1. Linux 계정 개요

### 계정이 보안의 첫 번째 방어선인 이유

- 공격자가 시스템에 접근하기 위해 가장 빈번하게 노리는 입구 중 하나는 **계정**이다.
- 외부에 노출된 SSH나 웹 로그인 서비스는 지속적으로 무차별 대입 공격의 대상이 될 수 있다.
- 약한 비밀번호가 공격에 의해 탈취되면 공격자는 일반 사용자 권한으로 시스템 내부에 접근할 수 있다.

### 약한 계정 관리와 권한 상승

- 약한 계정 관리는 권한 상승과 내부 이동의 출발점이 될 수 있다.
- 공격자는 시스템에 진입한 이후 다음과 같은 계정을 탐색할 수 있다.
  - UID 0 계정
  - 관리자 그룹의 구성원
  - 휴면 계정
  - 테스트 계정
  - 불필요하게 활성화된 계정
- 계정 및 권한 구조에 문제가 있으면 공격자가 더 높은 권한을 확보할 가능성이 증가한다.

### 지속적인 계정 관리의 필요성

- 계정 보안은 한 번 설정하고 끝나는 것이 아니라 운영 과정에서 지속적으로 관리해야 하는 영역이다.
- 인력이 변경되거나 시스템이 추가되면 계정과 권한도 함께 증가할 수 있다.
- 사용하지 않는 계정이나 불필요한 권한을 정리하지 않으면 시간이 지날수록 보안 상태가 약화될 수 있다.
- 따라서 정기적으로 계정과 권한 구조를 점검해야 한다.

> Linux 계정 보안을 점검하기 위해서는 먼저 Linux의 계정 구조와 계정 정보를 저장하는 방식을 이해해야 한다.

# 12. Linux 계정의 분류

Linux 계정은 일반적으로 **root 계정, 시스템 계정, 일반 사용자 계정**으로 구분할 수 있다.

| 구분 | 일반적인 UID 범위 | 역할 |
|---|---:|---|
| root | `0` | 시스템 전체에 대한 최고 권한을 가지며 관리자 작업을 수행한다. |
| 시스템 계정 | `1 ~ 999` | 서비스 및 데몬 실행 등을 위한 계정이다. |
| 일반 사용자 | `1000 이상` | 사람이 로그인하여 일상적인 작업을 수행하는 계정이다. |

> UID 범위는 배포판과 설정에 따라 차이가 있을 수 있으므로 실제 시스템의 정책을 함께 확인해야 한다.

## 12.1. root 계정

- root는 UID가 `0`인 특수 계정이다.
- 시스템 전체에 대한 강력한 권한을 가지므로 시스템 관리 및 보안 설정 변경 등에 사용된다.
- root 권한이 탈취되면 시스템 전체가 공격자에게 장악될 위험이 있다.

## 12.2. 시스템 계정

- 시스템 계정은 웹 서버, 데이터베이스, 로그 관리 등의 서비스나 데몬을 실행하기 위한 목적으로 사용된다.
- 일반적으로 사람이 직접 로그인하기 위한 계정이 아니므로 로그인 셸과 접근 권한을 적절하게 제한해야 한다.

## 12.3. 일반 사용자 계정

- 일반 사용자가 시스템에 로그인하여 작업을 수행하기 위한 계정이다.
- 일반적으로 root보다 제한된 권한을 가진다.
- 필요한 작업에 대해서만 적절한 권한을 부여하는 것이 중요하다.

# 13. Linux 계정 정보를 저장하는 주요 파일

Linux에서는 계정 및 그룹과 관련된 정보를 여러 파일을 통해 관리한다.

| 파일 | 주요 내용 |
|---|---|
| `/etc/passwd` | 계정의 기본 정보 |
| `/etc/shadow` | 비밀번호 해시 및 비밀번호 만료 정책 |
| `/etc/group` | 그룹 정보 및 그룹 구성원 |

- 세 파일은 Linux의 계정 및 권한 체계를 구성하는 중요한 파일이다.
- 특히 `/etc/shadow`에는 비밀번호 해시 등의 민감한 정보가 포함되므로 접근 권한을 엄격하게 관리해야 한다.

# 14. `/etc/passwd` 파일 구조

## 14.1. `/etc/passwd` 개요

- `/etc/passwd`의 각 행은 하나의 사용자 계정을 나타낸다.
- 각 필드는 콜론(`:`)으로 구분되며 총 **7개의 필드**로 구성된다.

```text
계정명:비밀번호:UID:GID:GECOS:홈디렉터리:로그인셸
```

## 14.2. 7개 필드

| 필드 | 의미 |
|---|---|
| 계정명 | 로그인할 때 사용하는 계정 이름이다. |
| 비밀번호 | 일반적으로 `x`가 표시되며 실제 비밀번호 해시는 `/etc/shadow`에 저장된다. |
| UID | 운영체제가 사용자를 식별하기 위한 번호이다. |
| GID | 사용자의 기본 그룹을 식별하는 번호이다. |
| GECOS | 사용자에 대한 보조 정보로 이름, 부서 등의 정보가 포함될 수 있다. |
| 홈 디렉터리 | 사용자가 로그인한 후 기본적으로 위치하는 디렉터리이다. |
| 로그인 셸 | 로그인 시 실행되는 셸 프로그램이다. |

### 예시

```text
user:x:1000:1000:User:/home/user:/bin/bash
```

- `user`: 계정명
- `x`: 실제 비밀번호 해시는 `/etc/shadow`에 저장된다.
- `1000`: UID
- `1000`: 기본 GID
- `User`: GECOS 정보
- `/home/user`: 홈 디렉터리
- `/bin/bash`: 로그인 셸

# 15. `/etc/shadow` 파일 구조

## 15.1. `/etc/shadow` 개요

- `/etc/shadow`는 사용자 비밀번호의 해시값과 비밀번호 만료 정책 등을 저장하는 보호된 파일이다.
- 일반적으로 일반 사용자가 직접 읽을 수 없도록 접근 권한을 제한한다.
- 각 행은 콜론(`:`)으로 구분된 **9개의 필드**로 구성된다.

```text
계정명:암호화된비밀번호:마지막변경일:최소사용기간:최대사용기간:경고기간:비활성기간:계정만료일:예약필드
```

## 15.2. 9개 필드

| 필드 | 의미 |
|---|---|
| 계정명 | `/etc/passwd`와 대응되는 계정 이름이다. |
| 암호화된 비밀번호 | 비밀번호의 해시값이 저장된다. |
| 마지막 변경일 | 비밀번호를 마지막으로 변경한 날짜를 1970-01-01 기준 경과 일수로 표시한다. |
| 최소 사용 기간 | 비밀번호를 변경한 후 다시 변경할 수 있을 때까지의 최소 일수이다. |
| 최대 사용 기간 | 비밀번호를 변경한 후 만료되기까지의 최대 일수이다. |
| 경고 기간 | 비밀번호 만료 전에 사용자에게 경고하는 기간이다. |
| 비활성 기간 | 비밀번호가 만료된 이후 계정이 비활성화되기까지의 기간이다. |
| 계정 만료일 | 계정 자체가 만료되는 날짜를 나타낸다. |
| 예약 필드 | 향후 사용을 위해 예약된 필드이다. |

> `/etc/shadow`의 접근 권한과 비밀번호 정책이 적절하게 설정되어 있는지 정기적으로 점검해야 한다.

# 16. `/etc/group` 파일 구조

## 16.1. `/etc/group` 개요

- `/etc/group`은 Linux 시스템에서 사용하는 그룹 정보를 저장한다.
- 일반적으로 다음과 같은 **4개의 필드**로 구성된다.

```text
그룹명:그룹비밀번호:GID:구성원목록
```

| 필드 | 의미 |
|---|---|
| 그룹명 | 그룹의 이름이다. |
| 그룹 비밀번호 | 그룹 변경 등에 사용될 수 있는 필드이며 일반적인 환경에서는 거의 사용하지 않는다. |
| GID | 그룹을 식별하는 번호이다. |
| 구성원 목록 | 해당 그룹에 포함된 사용자 목록이다. |

## 16.2. 기본 그룹과 보조 그룹

- 사용자는 `/etc/passwd`에 지정된 기본 그룹 외에도 여러 개의 보조 그룹(Secondary Group)에 소속될 수 있다.
- 그룹은 여러 사용자에게 동일한 파일 접근 권한 등을 부여할 때 활용할 수 있다.
- 사용자별로 권한을 하나씩 설정하는 것보다 그룹 단위로 관리하면 권한 관리가 효율적이다.

### 관리자 권한 그룹

- Linux 배포판에 따라 `sudo` 또는 `wheel`과 같은 그룹을 관리자 권한 위임에 사용할 수 있다.
- 따라서 이러한 그룹에 불필요한 사용자가 포함되어 있지 않은지 정기적으로 확인해야 한다.

# 17. root 계정과 `su`, `sudo`

## 17.1. 개념

- **root**는 시스템 전체에 대한 최고 수준의 권한을 가진 특수 계정이다.
- `su`와 `sudo`는 일반 사용자가 다른 사용자 권한으로 작업하거나 관리자 권한을 사용하기 위해 활용하는 명령이다.

## 17.2. `su`와 `sudo` 비교

| 구분 | `su` | `sudo` |
|---|---|---|
| 기본적인 인증 방식 | 전환 대상 계정의 비밀번호를 요구할 수 있다. | 일반적으로 명령을 실행하는 사용자의 비밀번호를 사용한다. |
| 권한 사용 방식 | 다른 계정의 셸로 전환할 수 있다. | 허용된 특정 명령을 다른 권한으로 실행한다. |
| 권한 범위 | 셸로 전환하면 해당 셸에서 대상 계정의 권한을 사용할 수 있다. | 필요한 명령에 한정하여 권한을 부여할 수 있다. |
| 감사 및 추적 | 셸 전환 이후 실행한 개별 명령을 별도로 추적하기 어려울 수 있다. | `sudo` 실행 기록을 통해 사용자와 명령 등을 추적하기 쉽다. |

> 실제 로그 기록 방식은 Linux 배포판과 `sudo`, PAM, 감사 로그 설정 등에 따라 달라질 수 있다.

## 17.3. `sudo`의 장점

- 관리자 권한이 필요한 작업만 선택적으로 허용할 수 있다.
- root 비밀번호를 여러 사용자에게 공유하지 않고도 관리자 작업을 수행할 수 있다.
- 사용자별 권한을 세분화할 수 있어 최소 권한 원칙을 적용하기에 유리하다.
- `sudoers` 정책을 통해 특정 사용자에게 허용되는 명령을 관리할 수 있다.

# 18. 계정 자체에 대한 위협 시나리오

## 18.1. 불필요한 UID 0 계정

- root 이외에 UID `0`을 가진 계정이 존재하면 root와 동일한 수준의 권한을 가질 수 있다.
- 따라서 root 이외의 UID 0 계정이 불필요하게 존재하지 않는지 확인해야 한다.

## 18.2. 휴면 및 테스트 계정

- 사용하지 않는 휴면 계정이나 테스트 계정을 방치하면 공격자가 악용할 수 있는 진입점이 될 수 있다.
- 사용이 종료된 계정은 삭제하거나 비활성화해야 한다.

## 18.3. 과도한 관리자 그룹 권한

- 관리자 권한을 가진 그룹에 불필요한 사용자가 포함되어 있으면 권한이 과도하게 확산될 수 있다.
- 관리자 그룹의 구성원을 정기적으로 검토하고 업무상 필요한 사용자에게만 권한을 부여해야 한다.

## 18.4. 기본 그룹 정보 불일치

- `/etc/passwd`에서 사용자의 GID를 확인하고 해당 GID가 실제 그룹 정보와 정상적으로 연결되는지 확인해야 한다.
- 계정과 그룹 정보가 일관되지 않으면 권한 관리에 문제가 발생할 수 있다.

## 18.5. UID 공유

- 여러 사용자가 동일한 UID를 공유하면 시스템 입장에서 동일한 사용자로 인식될 수 있다.
- 이 경우 사용자를 개별적으로 식별하기 어려워져 감사 및 책임 추적에 문제가 발생할 수 있다.
- 따라서 원칙적으로 사용자별 개별 계정을 사용해야 한다.

# 19. 권한과 세션에 대한 위협 시나리오

## 19.1. `su`를 이용한 root 전환

- 일반 사용자가 `su`를 통해 root 계정으로 전환할 수 있도록 허용된 경우 root 인증 정보에 대한 공격 시도가 발생할 수 있다.
- 일반 계정이 침해된 상황에서는 이러한 권한 전환 경로가 추가적인 공격 표면이 될 수 있다.
- 따라서 root 로그인 및 권한 전환 정책을 적절하게 관리해야 한다.

## 19.2. 시스템 계정의 로그인 셸

- 시스템 계정에 `/bin/bash`와 같은 일반 로그인 셸이 설정되어 있으면 의도하지 않은 직접 로그인이 가능해질 수 있다.
- 사람이 직접 로그인할 필요가 없는 서비스 계정은 적절한 로그인 셸을 설정하여 불필요한 접근을 제한해야 한다.

## 19.3. 세션 타임아웃

- 세션 타임아웃이 적절하게 설정되어 있지 않으면 사용자가 자리를 비운 동안 인증된 세션이 그대로 유지될 수 있다.
- 특히 관리자 권한으로 접속한 세션은 방치되지 않도록 적절한 세션 관리 정책을 적용해야 한다.

## 19.4. 계정 보안과 사용 방식

- 계정 보안은 단순히 **"어떤 계정이 존재하는가"**만 확인하는 것이 아니다.
- 계정이 **"어떤 권한을 가지고 어떻게 사용되는가"**까지 함께 점검해야 한다.
- 따라서 계정 관리에서는 다음 항목을 종합적으로 확인해야 한다.

```text
계정 존재 여부
    ↓
UID / GID 확인
    ↓
그룹 및 권한 확인
    ↓
로그인 셸 확인
    ↓
비밀번호 정책 확인
    ↓
관리자 권한 확인
    ↓
휴면·불필요 계정 확인
    ↓
세션 및 접근 정책 확인
```

1. **계정은 시스템 보안의 중요한 첫 번째 방어선이다.**
   - 외부에 노출된 로그인 서비스가 공격 대상이 될 수 있으므로 계정과 인증 정보를 안전하게 관리해야 한다.

2. **Linux 계정은 권한에 따라 구분된다.**
   - root, 시스템 계정, 일반 사용자 계정의 역할과 권한 범위를 이해해야 한다.

3. **계정 정보 파일을 이해해야 한다.**
   - `/etc/passwd`, `/etc/shadow`, `/etc/group`은 Linux 계정 및 그룹 관리의 핵심 파일이다.

4. **UID와 GID를 확인해야 한다.**
   - 특히 UID `0` 계정과 관리자 그룹의 구성원을 점검하여 불필요한 관리자 권한이 존재하지 않는지 확인해야 한다.

5. **사용하지 않는 계정을 관리해야 한다.**
   - 휴면 계정, 테스트 계정, 퇴사자 계정 등 불필요한 계정을 방치하지 않아야 한다.

6. **최소 권한 원칙을 적용해야 한다.**
   - 사용자에게 업무에 필요한 권한만 부여하고 관리자 권한은 최소한으로 제한해야 한다.

7. **`su`와 `sudo`의 차이를 이해해야 한다.**
   - `su`는 다른 계정으로 전환하는 방식이고, `sudo`는 허용된 명령에 대해 필요한 권한을 부여하는 방식이다.
   - 일반적으로 `sudo`를 활용하면 관리자 권한을 보다 세분화하여 관리할 수 있다.

8. **계정 자체뿐만 아니라 사용 방식까지 점검해야 한다.**
   - 로그인 셸, 관리자 권한, 세션 타임아웃, 권한 전환 정책 등을 함께 확인해야 한다.

9. **계정 보안은 지속적인 관리가 필요하다.**
   - 시스템과 인력의 변화에 따라 계정과 권한도 계속 변화하므로 정기적인 점검과 불필요한 권한 제거가 필요하다.
