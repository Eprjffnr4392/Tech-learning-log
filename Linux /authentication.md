# 1. 약한 비밀번호가 뚫리는 이유

비밀번호는 시스템에 접근하기 위한 가장 흔하고 기본적인 인증 수단이다.

- 외부에서 시스템에 접근하려면 어떤 형태로든 인증을 통과해야 하며, 그 첫 번째 수단이 비밀번호인 경우가 많다.
- 따라서 비밀번호의 강도는 인증 단계의 보안 수준에 직접적인 영향을 미친다.
- 약한 비밀번호는 시스템 침투의 첫 번째 통로가 될 수 있다.

공격자는 정교한 공격 기법을 사용하기 전에 비밀번호 추측부터 시도할 수 있다.

- 비밀번호 추측이 성공하면 추가적인 취약점 없이도 정상 사용자처럼 시스템에 접근할 수 있다.
- 공격자는 자동화 도구를 이용하여 비밀번호를 반복적으로 시도할 수 있다.
- 인터넷에 노출된 Linux 서버의 SSH나 웹 로그인 서비스는 지속적인 로그인 시도에 노출될 수 있다.
- 이러한 공격은 사람이 직접 수행하기보다 봇이나 스크립트를 이용해 자동화되는 경우가 많다.

결국 **비밀번호 정책의 수준이 시스템 인증 보안의 중요한 요소**가 된다.

---

# 2. 비밀번호 공격 유형

공격자가 비밀번호를 알아내기 위해 사용하는 방식은 크게 다음과 같이 구분할 수 있다.

| 공격 유형 | 원리 | 주요 대응 |
|---|---|---|
| 무차별 대입(Brute Force) | 가능한 모든 문자 조합을 반복적으로 시도한다. | 비밀번호 길이 및 복잡도 강화, 로그인 시도 제한 |
| 사전 공격(Dictionary Attack) | 자주 사용하는 단어, 이름, 키보드 패턴 등을 이용해 비밀번호를 추측한다. | 사전 단어 및 예측 가능한 패턴 사용 금지 |
| 자격증명 스터핑(Credential Stuffing) | 다른 사이트에서 유출된 계정·비밀번호 조합을 재사용하여 로그인을 시도한다. | 사이트마다 서로 다른 비밀번호 사용, MFA 적용 |

# 3. 안전한 비밀번호 정책의 5가지 요소

비밀번호 정책은 여러 보안 요소가 함께 적용될 때 효과적인 방어 수단이 된다.

| 요소 | 방어 효과 |
|---|---|
| 길이(Length) | 비밀번호 추측에 필요한 경우의 수를 크게 증가시킨다. |
| 복잡도(Complexity) | 단순한 사전 단어와 예측 가능한 패턴 사용을 어렵게 한다. |
| 최대 사용 기간(Aging) | 장기간 동일한 비밀번호를 사용하는 위험을 줄인다. |
| 이력 관리(History) | 기존에 사용했던 비밀번호의 재사용을 방지한다. |
| 계정 잠금(Lockout) | 반복적인 로그인 실패를 제한하여 온라인 공격을 어렵게 한다. |

단, 실제 환경에서는 단순히 비밀번호를 자주 변경하도록 강제하는 것보다 **길고 추측하기 어려운 비밀번호 사용, 재사용 방지, 다중 인증(MFA), 로그인 시도 제한** 등을 종합적으로 적용하는 것이 중요하다.

# 4. 비밀번호 길이와 복잡도 정책

비밀번호가 길고 예측하기 어려울수록 무차별 대입 공격에 필요한 시도 횟수가 크게 증가한다.

- 짧은 비밀번호는 가능한 조합의 수가 상대적으로 적어 공격자가 빠르게 추측할 가능성이 높다.
- 비밀번호의 길이가 증가하면 가능한 조합의 수가 급격하게 증가한다.
- 공격자가 하나의 비밀번호에 무한정 시간을 사용할 수 없기 때문에 충분한 길이는 중요한 방어 수단이 된다.
- 일반적으로 최소 8자 이상을 요구하는 정책이 사용되어 왔으며, 실제 보안 환경에서는 더 긴 비밀번호나 패스프레이즈 사용을 권장하는 경우가 많다.
- 영문 대소문자, 숫자, 특수문자 등을 조합하면 가능한 문자 공간을 증가시킬 수 있다.

다만 복잡도만으로 충분한 것은 아니다.

예를 들어 길이가 긴 비밀번호라도 사전 단어나 키보드 패턴처럼 예측하기 쉬운 형태라면 사전 공격이나 패턴 기반 공격에 노출될 수 있다.

따라서 **길이와 예측 불가능성을 함께 고려**해야 한다.

# 5. 비밀번호 사용 기간과 이력 관리

## 5.1 최대 사용 기간(Aging)

최대 사용 기간은 일정 기간이 지나면 비밀번호를 변경하도록 설정하는 정책이다.

예를 들어 일정 주기로 비밀번호를 변경하도록 설정하면 장기간 동일한 비밀번호를 사용하는 위험을 줄일 수 있다.

다만 비밀번호가 유출되지 않았음에도 너무 짧은 주기로 변경을 강제하면 사용자가 기억하기 쉬운 단순한 비밀번호를 반복해서 사용하거나 이전 비밀번호를 변형하는 등의 문제가 발생할 수 있다.

따라서 조직의 보안 정책과 환경에 맞게 적절하게 설정해야 한다.

## 5.2 이력 관리(Password History)

이력 관리는 최근에 사용한 비밀번호를 다시 사용하지 못하도록 제한하는 정책이다.

- 비밀번호 변경을 강제하더라도 사용자가 이전 비밀번호로 되돌아가면 정책의 효과가 감소한다.
- 비밀번호 이력 관리를 적용하면 최근 사용한 비밀번호의 재사용을 방지할 수 있다.
- 이를 통해 비밀번호 변경이 실제 보안 강화로 이어지도록 할 수 있다.

# 6. 계정 잠금 정책

계정 잠금은 일정 횟수 이상 비밀번호 인증에 실패하면 해당 계정을 일시적으로 잠그는 정책이다.

- 반복적인 로그인 시도 자체를 제한하여 온라인 무차별 대입 공격을 어렵게 만든다.
- 예를 들어 로그인 실패가 일정 횟수 이상 발생하면 일정 시간 동안 추가 로그인을 제한할 수 있다.
- 공격자가 자동화 도구를 이용해 대량의 비밀번호를 시도하는 것을 어렵게 만들 수 있다.

계정 잠금 정책을 설정할 때는 **실패 횟수와 잠금 지속 시간**을 함께 고려해야 한다.

예를 들어 다음과 같은 정책을 사용할 수 있다.

- 일정 횟수 로그인 실패 → 계정 일시 잠금
- 일정 시간이 지나면 자동으로 잠금 해제

잠금 시간이 지나치게 짧으면 공격 방어 효과가 감소할 수 있고, 반대로 지나치게 길면 정상 사용자가 서비스를 이용하기 어려워질 수 있다.

또한 공격자가 의도적으로 로그인 실패를 발생시켜 정상 사용자의 계정을 잠그는 **계정 잠금 기반 서비스 거부 공격**도 고려해야 한다.

# 7. PAM의 역할

**PAM(Pluggable Authentication Modules)**은 Linux에서 인증 기능을 모듈화하여 관리하기 위한 시스템이다.

PAM을 사용하면 인증과 관련된 정책을 각각의 모듈로 구성할 수 있다.

주요 기능은 다음과 같다.

- 비밀번호 인증 및 검사
- 계정 잠금
- 인증 실패 횟수 제한
- 비밀번호 이력 관리
- 계정 및 세션 관리
- 다중 인증 등 추가 인증 기능

Linux에서 로그인, `sudo`, SSH 등 인증이 필요한 다양한 서비스에서 PAM이 사용될 수 있다.

PAM 설정은 일반적으로 `/etc/pam.d/` 디렉터리 아래의 서비스별 설정 파일을 통해 관리한다.

예를 들어 SSH 인증과 관련된 설정에는 다음 파일이 사용될 수 있다.

```bash
/etc/pam.d/sshd
```

서비스마다 별도의 PAM 설정을 사용하기 때문에 인증 흐름을 세밀하게 제어할 수 있다.

비밀번호 검사, 계정 잠금, 이력 관리 등의 기능은 PAM 모듈을 통해 적용할 수 있으며, 계정의 기본적인 비밀번호 사용 기간 등의 정책은 `/etc/login.defs`와 같은 설정을 통해 관리할 수 있다.

단, 실제 동작은 배포판과 PAM 구성에 따라 달라질 수 있으므로 설정 파일을 확인하여 적용된 정책을 확인해야 한다.

# 8. 비밀번호 해시 알고리즘

Linux에서는 일반적으로 사용자의 비밀번호를 평문으로 저장하지 않고 해시 기반 형태로 저장한다.

비밀번호 관련 정보는 `/etc/shadow`에 저장되며, 사용하는 해시 방식은 해시 문자열 앞의 식별자를 통해 확인할 수 있다.

| 식별자 | 알고리즘 | 특징 |
|---|---|---|
| `$1$` | MD5 | 현재 비밀번호 저장 용도로는 안전하지 않아 사용을 피해야 한다. |
| `$5$` | SHA-256 | SHA 계열 해시 방식이다. |
| `$6$` | SHA-512 | SHA-256보다 긴 해시를 사용하는 방식이다. |
| `$y$` | yescrypt | 최신 Linux 배포판에서 사용되는 비밀번호 해싱 방식 중 하나이다. |

비밀번호 저장에서는 단순한 빠른 해시보다 공격자가 대량의 비밀번호 후보를 계산하기 어렵도록 설계된 **비밀번호 전용 해싱 방식**을 사용하는 것이 중요하다.

또한 실제 사용 가능한 알고리즘과 기본값은 Linux 배포판 및 버전에 따라 달라질 수 있다.

# 9. `/etc/shadow` 파일 보호의 중요성

`/etc/shadow`는 Linux 시스템의 계정별 비밀번호 인증 정보가 저장되는 매우 중요한 파일이다.

이 파일이 공격자에게 유출되면 공격자는 자신의 시스템에서 비밀번호 해시를 대상으로 오프라인 크래킹을 시도할 수 있다.

온라인 공격과 달리 오프라인 크래킹은 대상 서버의 로그인 횟수 제한이나 계정 잠금 정책의 직접적인 영향을 받지 않는다.

따라서 공격자는 자신의 컴퓨팅 자원을 이용하여 많은 비밀번호 후보를 반복적으로 계산할 수 있다.

`/etc/shadow`는 일반 사용자가 임의로 읽을 수 없도록 엄격하게 보호해야 한다.

비밀번호 정책이 강력하더라도 `/etc/shadow`와 같은 인증 정보가 유출되면 공격자가 별도의 환경에서 비밀번호 추측을 수행할 수 있으므로 파일 접근 권한과 시스템 보안 역시 중요하다.

---

# 10. 공격자 관점에서 본 비밀번호 보안

공격자는 외부에 노출된 SSH나 웹 로그인 서비스를 대상으로 비밀번호 공격을 자동화할 수 있다.

일반적인 공격 흐름은 다음과 같이 정리할 수 있다.

1. 외부에 노출된 로그인 서비스를 탐색한다.
2. 계정 이름이나 이메일 주소 등의 인증 정보를 확보한다.
3. 무차별 대입이나 사전 공격 등을 자동화하여 로그인을 시도한다.
4. 약한 비밀번호가 사용된 계정에 로그인한다.
5. 획득한 계정의 권한과 접근 범위를 확인한다.
6. 추가적인 인증 정보나 민감한 데이터를 확보하려고 시도한다.
7. 인증 정보가 추가로 유출되면 오프라인 크래킹 등의 방법을 통해 다른 계정으로 공격 범위를 확대할 수 있다.

따라서 비밀번호 보안은 단순히 비밀번호 하나의 강도만 관리하는 것이 아니라 **인증 과정 전체를 보호하는 관점**에서 접근해야 한다.

# 11. 핵심내용 (Summary)

- 약한 비밀번호는 시스템 침투의 주요 진입점이 될 수 있다.
- 비밀번호 공격에는 무차별 대입, 사전 공격, 자격증명 스터핑 등이 있다.
- 충분한 비밀번호 길이와 예측하기 어려운 비밀번호를 사용하는 것이 중요하다.
- 비밀번호 재사용을 방지하기 위해 이력 관리 정책을 적용할 수 있다.
- 비밀번호 사용 기간 정책은 환경에 맞게 적절하게 설정해야 한다.
- 계정 잠금은 온라인 무차별 대입 공격을 제한하는 중요한 보안 정책이다.
- PAM은 Linux의 인증 및 계정 관리 정책을 모듈 형태로 적용할 수 있도록 한다.
- `/etc/shadow`에는 중요한 비밀번호 인증 정보가 저장되므로 접근 권한을 엄격하게 관리해야 한다.
- `/etc/shadow`가 유출되면 공격자가 오프라인 환경에서 비밀번호 크래킹을 수행할 수 있다.
- 비밀번호 보안은 길이, 예측 가능성, 재사용 방지, 인증 시도 제한, MFA 등을 종합적으로 고려해야 한다.
