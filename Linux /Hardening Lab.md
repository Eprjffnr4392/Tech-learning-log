# 21. Linux 계정 보안 점검 및 하드닝 실습

## 21.1 Linux 계정 보안 점검 및 하드닝 개요

Linux 계정 관리 점검 항목은 U-01부터 U-13까지 총 13개 항목으로 구성되어 있으며, 이 실습에서는 다음 두 항목을 진행한다.

- **U-05**: root 이외의 UID가 `0`인 계정 금지
- **U-07**: 불필요한 계정 제거

---

## 21.2 U-05 root 이외의 UID가 `0`인 계정 금지

### 21.2.1 점검 내용

사용자 계정 정보가 저장된 `/etc/passwd`, `/etc/shadow` 등의 파일을 확인하여 `root(UID=0)` 계정과 동일한 UID를 가진 계정이 존재하는지 점검한다.

### 21.2.2 점검 목적

root 계정과 동일한 UID를 가진 계정이 존재하는지 확인하여 root 권한이 일반 사용자 계정이나 비인가 계정에 부여될 가능성이 있는지 점검한다.

### 21.2.3 보안 위협

root 계정과 동일한 UID가 설정된 일반 사용자 계정은 사실상 root와 동일한 권한을 가지게 된다.

따라서 해당 계정으로 다음과 같은 작업이 가능해질 수 있다.

- 서비스 시작 및 중지
- 시스템 재부팅
- root 권한이 필요한 파일 편집
- 시스템 설정 변경
- 기타 root 권한이 필요한 작업 수행

또한 root 계정과 동일한 UID를 사용하기 때문에 사용자 감사 및 추적이 어려워질 수 있다.

### 21.2.4 참고

UID(User ID)는 운영체제에서 사용자를 식별하기 위해 사용하는 숫자형 식별자이다.

OS마다 UID 체계와 시스템 계정 및 일반 사용자 계정에 할당되는 범위에는 차이가 있을 수 있지만, 일반적으로 관리자인 root 계정에는 UID `0`이 할당된다.

### 21.2.5 판단 기준

| 구분 | 판단 기준 |
|---|---|
| 양호 | root 계정과 동일한 UID를 갖는 계정이 존재하지 않는 경우 |
| 취약 | root 계정과 동일한 UID를 갖는 계정이 존재하는 경우 |

## 21.3 U-05 root 이외의 UID 0 점검 실습

`/etc/passwd` 파일에서 UID가 `0`인 계정을 `awk` 명령어로 추출한다.

```bash
$ awk -F: '($3==0) {print $1}' /etc/passwd
root
```

출력 결과가 `root`만 존재하므로 root 이외의 UID `0` 계정이 존재하지 않는 것으로 판단한다.

따라서 해당 시스템은 **U-05 항목에서 양호한 상태**로 판정한다.

## 21.4 U-07 불필요한 계정 제거

### 21.4.1 점검 내용

시스템에 등록된 계정 중 불필요한 계정이 존재하는지 점검한다.

다음과 같은 계정을 주요 점검 대상으로 한다.

- 퇴직으로 더 이상 사용하지 않는 계정
- 전직 또는 업무 변경으로 사용하지 않는 계정
- 휴직으로 장기간 사용하지 않는 계정
- 장기간 로그인하지 않은 계정
- 테스트 및 임시 목적으로 생성한 계정
- 기타 업무상 사용하지 않는 계정

### 21.4.2 점검 목적

사용하지 않는 불필요한 계정이 존재하는지 확인하여 관리되지 않는 계정을 통한 침입 가능성을 줄이는 것을 목적으로 한다.

### 21.4.3 보안 위협

로그인이 가능하면서 현재 사용하지 않는 불필요한 계정은 정상적으로 사용하는 계정보다 관리가 소홀할 가능성이 있다.

공격자는 이러한 계정을 대상으로 비밀번호 추측이나 탈취 등을 시도할 수 있으며, 계정이 탈취될 경우 시스템에 대한 비인가 접근으로 이어질 수 있다.

따라서 퇴직, 전직, 휴직 등의 사유가 발생하면 불필요한 계정의 권한을 즉시 회수하거나 계정을 잠그는 것을 권고한다.

### 21.4.4 참고

**기본 계정**은 운영체제 또는 패키지를 설치하는 과정에서 기본적으로 생성되는 계정이다.

예를 들어 다음과 같은 계정이 존재할 수 있다.

- `lp`
- `uucp`
- `nuucp`

다만 기본 계정이라고 해서 무조건 삭제해서는 안 된다.

계정을 삭제하기 전에 해당 계정이 시스템 서비스나 특정 애플리케이션에서 사용되는지 확인하고, 삭제로 인해 발생할 수 있는 업무 및 서비스 영향을 검토해야 한다.

### 21.4.5 판단 기준

| 구분 | 판단 기준 |
|---|---|
| 양호 | 불필요한 계정이 존재하지 않는 경우 |
| 취약 | 불필요한 계정이 존재하는 경우 |

## 21.5 U-07 불필요한 계정 점검 실습 — 일반 사용자 목록

먼저 시스템에 등록된 일반 사용자 계정을 확인한다.

실습에서는 UID가 `1000` 이상이고 `60000` 미만인 계정을 추출한다.

```bash
$ awk -F: '($3>=1000 && $3<60000) {print $1}' /etc/passwd
user
testuser
```

출력 결과에서 `user` 외에 `testuser` 계정이 식별된다.

실습에서는 `testuser`를 시스템 초기 구축 과정에서 테스트 목적으로 생성한 계정이라고 가정한다.

따라서 현재 사용하지 않는 테스트 계정이라면 U-07 점검 대상에 해당한다.

## 21.6 U-07 불필요한 계정 점검 실습 — 휴면 계정 식별

`lastlog` 명령어를 사용하여 한 번도 로그인한 기록이 없는 계정을 확인한다.

```bash
$ lastlog | grep "Never logged in"
backup           **Never logged in**
list             **Never logged in**
gnats            **Never logged in**
nobody           **Never logged in**
systemd-network  **Never logged in**
systemd-resolve  **Never logged in**
syslog           **Never logged in**
...
testuser         **Never logged in**
```

출력된 계정 중에는 시스템 서비스에서 사용하는 계정도 포함될 수 있다.

따라서 `Never logged in`으로 출력되었다는 이유만으로 모든 계정을 삭제해서는 안 된다.

특히 `UID < 1000`과 같은 시스템 계정은 운영체제 및 서비스에서 사용할 수 있으므로 해당 계정의 용도를 먼저 확인해야 한다.

실습 환경에서는 일반 사용자 계정 중 장기간 사용하지 않는 계정이 `testuser` 하나라고 가정한다.

따라서 `testuser`를 불필요한 계정으로 판단하여 조치한다.

## 21.7 U-07 불필요한 계정 조치 실습

불필요한 계정은 즉시 삭제하기보다는 **계정 잠금 → 일정 기간 확인 → 필요 시 삭제**의 단계로 조치하는 것이 안전하다.

### 21.7.1 1단계 — 계정 잠금

먼저 계정을 잠가 로그인을 차단한다.

```bash
# 1단계 — 계정 잠금
$ sudo usermod -L testuser
```

계정 잠금 이후 해당 계정이 실제로 사용되지 않는지 확인한다.

### 21.7.2 2단계 — 확인 후 완전 삭제

더 이상 사용할 필요가 없다고 판단되면 계정을 삭제한다.

```bash
# 2단계 — 확인 후 완전 삭제 (홈 디렉터리 포함)
$ sudo userdel -r testuser
```

`-r` 옵션을 사용하면 해당 계정의 홈 디렉터리 및 관련 파일을 함께 삭제할 수 있으므로, 삭제 전에 필요한 데이터가 남아 있는지 확인해야 한다.

### 21.7.3 조치 후 재점검

계정 삭제 후 일반 사용자 계정 목록을 다시 확인한다.

```bash
$ awk -F: '($3>=1000 && $3<60000) {print $1}' /etc/passwd
student
```

`testuser` 계정이 더 이상 출력되지 않으므로 불필요한 테스트 계정이 정리된 것을 확인할 수 있다.

따라서 실습 환경에서는 **U-07 항목이 양호한 상태로 전환된 것**으로 판단한다.

## 21.8 U-05와 U-07 핵심 정리

| 점검 항목 | 점검 내용 | 주요 명령어 | 실습 결과 |
|---|---|---|---|
| U-05 | root 이외의 UID `0` 계정 존재 여부 | `awk` | `root`만 존재하여 양호 |
| U-07 | 불필요한 일반 사용자 계정 존재 여부 | `awk`, `lastlog` | `testuser` 식별 후 삭제하여 양호 |

### 핵심 내용

- UID `0`은 root 권한과 연결되므로 root 이외의 계정이 UID `0`을 사용하는지 반드시 확인한다.
- `/etc/passwd`에서 UID 값을 기준으로 계정을 점검할 수 있다.
- `lastlog`는 로그인 기록을 확인하는 데 사용할 수 있지만, `Never logged in`인 계정이 모두 불필요한 계정인 것은 아니다.
- 시스템 서비스용 계정은 서비스 동작에 필요할 수 있으므로 용도를 확인한 후 조치한다.
- 불필요한 계정은 우선 잠금한 후 사용 여부를 확인하고 삭제하는 방식으로 안전하게 관리한다.
- 계정을 삭제할 때는 홈 디렉터리와 업무 데이터가 함께 삭제될 수 있으므로 사전에 필요한 데이터를 확인한다.
```

원문 명령어와 이미지 태그는 그대로 유지하면서, **U-05 → U-07 점검 → 조치 → 재점검** 흐름이 드러나도록 정리했다.
