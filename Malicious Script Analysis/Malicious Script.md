## 악성 스크립트 이해와 공격 개요

* 악성 스크립트(Malicious Script)는 피해자 시스템에서 공격자가 의도한 악성 행위를 수행하도록 작성된 스크립트 코드이다.
  - 실행 파일(`.exe`, `.dll`)과 달리 일반적으로 사람이 읽을 수 있는 텍스트 형태로 작성되며, 운영체제나 별도의 실행 환경에 포함된 인터프리터가 코드를 해석하여 실행한다.
  - 대표적인 실행 환경으로 PowerShell, Windows Script Host(WSH)의 `wscript.exe`/`cscript.exe`, `cmd.exe`, `mshta.exe` 등이 있다.
  - 스크립트 자체가 악성일 수도 있고, 정상적인 스크립트 인터프리터가 공격자의 명령을 실행하는 방식으로 악용될 수도 있다.

* 공격자는 별도의 악성 실행 파일을 직접 배포하지 않고, 운영체제에 기본적으로 존재하는 정상적인 인터프리터나 도구를 이용하여 악성 행위를 수행할 수 있다.
  - 정상적인 프로세스가 악성 명령을 실행하는 형태이기 때문에 단순한 파일 기반 탐지만으로는 탐지가 어려울 수 있다.
  - PowerShell과 같은 정상적인 관리 도구가 공격에 악용되는 경우를 LOLBin(Living Off the Land Binary) 또는 LOLBAS(Living Off the Land Binaries and Scripts)와 연관하여 분석할 수 있다.
  - 파일리스(Fileless) 공격은 악성 행위가 디스크에 파일로 저장되는 과정을 최소화하고 메모리나 정상적인 시스템 기능을 이용하여 수행하는 공격을 의미한다.
  - 따라서 악성 스크립트 공격과 파일리스 공격은 동일한 개념이 아니다. 악성 스크립트가 `.ps1`, `.vbs`, `.hta` 등의 형태로 디스크에 저장되는 경우도 많다.

### 악성 스크립트의 주요 종류

스크립트 언어별로 실행 환경과 악용되는 시스템 기능이 다르며, 공격자는 공격 목적에 따라 여러 종류의 스크립트와 시스템 도구를 조합한다.

1) **PowerShell (`.ps1`)**
   - Windows 환경에서 시스템 관리와 자동화에 사용되는 스크립팅 환경
   - 공격자가 명령 실행, 시스템 정보 수집, 다운로드, 프로세스 실행 등에 악용할 수 있음
   - `-EncodedCommand`와 같은 기능이 악성 명령의 난독화에 악용되는 사례가 있음
   - 메모리 내에서 동작하도록 구성할 경우 파일리스 공격과 결합될 수 있음
   - 분석 시 PowerShell Script Block Logging, AMSI, 프로세스 생성 이벤트 등을 확인할 수 있음

2) **VBScript / JScript**
   - Windows Script Host(WSH) 환경에서 실행되는 스크립트
   - `wscript.exe`, `cscript.exe` 등의 프로세스를 통해 실행
   - 이메일 첨부파일, 문서, 바로가기 파일 등의 초기 침투 과정에서 악용되는 사례가 있음
   - `WScript.Shell`, `FileSystemObject` 등의 정상적인 객체가 악성 행위에 악용될 수 있음

3) **HTA (`.hta`)**
   - HTML Application 형태의 스크립트 파일
   - `mshta.exe`를 통해 실행되며 HTML과 스크립트를 함께 사용할 수 있음
   - 일반적인 웹 브라우저의 보안 모델과 동일한 환경에서 실행되는 것이 아니므로 공격에 악용될 수 있음
   - 외부에서 가져온 콘텐츠나 스크립트를 실행하도록 구성되는 사례가 있음

4) **BAT / CMD (`.bat`, `.cmd`)**
   - Windows 명령 셸(`cmd.exe`)에서 실행되는 배치 스크립트
   - 시스템 명령 실행 및 다른 프로그램 호출에 악용될 수 있음
   - 환경 변수, 문자열 조합, 제어문 등을 이용한 난독화가 사용되기도 함
   - 다른 스크립트나 실행 파일을 호출하는 중간 단계 또는 드로퍼(Downloader/Dropper)의 역할로 사용될 수 있음

5) **AutoIt (`.au3`)**
   - Windows GUI 자동화 등에 사용되는 스크립트 언어
   - 스크립트를 컴파일하여 실행 파일 형태로 배포할 수 있음
   - 정상적인 자동화 프로그램으로 위장하거나 악성 행위를 포함하는 형태로 악용될 수 있음
   - 분석 시 컴파일된 실행 파일 내부의 스크립트 구조와 API 호출, 프로세스 생성 등의 행위를 확인할 필요가 있음

6) **Office 매크로(VBA)**
   - Microsoft Office 문서에서 자동화 기능을 제공하는 VBA 기반 코드
   - `AutoOpen`, `Document_Open` 등의 이벤트가 악성 행위의 자동 실행 트리거로 악용될 수 있음
   - 문서가 열렸을 때 PowerShell, `cmd.exe` 등의 프로세스를 실행하여 다음 단계의 페이로드를 실행하는 형태로 사용될 수 있음
   - 최신 Office 환경에서는 인터넷에서 받은 문서의 매크로 실행이 제한되는 등 보안 기능이 강화되었기 때문에 공격자는 다른 초기 침투 기법과 조합하기도 함


# 왜 스크립트가 공격 벡터로 활용되는가

- 실행 파일 기반 악성코드는 파일 자체의 구조와 문자열, 해시, 행위 등을 분석하여 탐지할 수 있으며, EDR은 프로세스 실행과 파일 생성 등의 행위까지 함께 분석한다.
- 공격자는 이러한 탐지를 우회하거나 분석을 어렵게 하기 위해 정상적인 스크립트 인터프리터와 시스템 관리 도구를 악용할 수 있다.
- 스크립트는 텍스트 기반이므로 코드의 일부를 암호화하거나 인코딩하고, 문자열을 여러 부분으로 분리하는 등의 난독화가 비교적 쉽게 이루어진다.
- 정상적인 시스템 구성 요소를 이용하면 별도의 악성 프로그램을 추가로 설치하지 않고도 일정 수준의 악성 행위를 수행할 수 있다.
- PowerShell, `cmd.exe`, `wscript.exe`, `mshta.exe` 등의 정상적인 시스템 도구가 악성 행위에 사용될 경우 프로세스 트리와 실행 인자, 부모-자식 프로세스 관계를 함께 분석해야 한다.
- 따라서 악성 스크립트 분석에서는 단순히 "파일이 악성인가?"만 판단하는 것이 아니라 다음과 같은 행위를 종합적으로 확인해야 한다.
  - 어떤 프로세스가 스크립트를 실행했는가?
  - 어떤 명령과 인자가 전달되었는가?
  - 외부 네트워크와 통신했는가?
  - 추가 파일이나 프로세스를 생성했는가?
  - 레지스트리나 작업 스케줄러 등을 이용해 지속성(Persistence)을 확보했는가?
  - 최종적으로 어떤 페이로드를 실행했는가?


# 악성 스크립트 감염 체인

* 악성 스크립트 공격은 하나의 스크립트가 모든 악성 행위를 수행하기보다 여러 단계를 거쳐 최종 페이로드를 실행하는 방식으로 구성되는 경우가 많다.

### 감염 체인의 주요 설계 원리

1) **정상 파일로 위장**
   - LNK, ISO, ZIP, Office 문서, PDF, HWP, OneNote 등의 파일을 정상적인 문서나 자료처럼 위장하여 사용자에게 전달
   - 사용자가 파일을 열거나 특정 동작을 수행하도록 유도하여 다음 단계 실행

2) **단계 분리**
   - 초기 단계에서는 단순한 스크립트나 로더만 실행하고 실제 악성 기능은 이후 단계에서 가져오도록 구성
   - 각 단계가 서로 다른 역할을 담당하므로 개별 파일이나 스크립트만 분석하면 전체 공격 흐름을 파악하기 어려울 수 있음
   - 1차 로더 → 2차 스크립트 → 최종 페이로드와 같은 다단계 구조가 사용될 수 있음

3) **정상 시스템 도구 악용**
   - PowerShell, `cmd.exe`, `wscript.exe`, `cscript.exe`, `mshta.exe`, `rundll32.exe` 등의 정상적인 시스템 구성 요소를 악성 행위에 활용
   - 별도의 공격용 실행 파일 대신 운영체제에 이미 존재하는 기능을 활용하여 탐지를 어렵게 만들 수 있음


### 실제 공격 흐름의 대표적인 형태

**1단계 - 미끼 / 전달 파일**

- 이메일이나 메신저 등을 통해 악성 파일 전달
- LNK, ISO, ZIP, Office 문서, HWP, OneNote 등의 파일이 초기 전달 수단으로 사용될 수 있음
- 사용자의 클릭이나 문서 실행 등의 행위를 통해 다음 단계가 시작됨
- 최근에는 사용자가 직접 특정 명령을 실행하도록 유도하는 ClickFix 계열의 사회공학적 기법도 사용됨


**2단계 - 악성 스크립트 / 로더**

- PowerShell, VBScript, JScript, BAT 등의 스크립트가 실행
- 코드 난독화, 인코딩, 문자열 분할 등을 이용하여 분석을 방해
- 외부 서버와 통신하여 추가 데이터를 가져오거나 다음 단계의 페이로드를 실행
- 이 단계에서 시스템 정보 수집, 환경 확인, 보안 제품 확인 등의 행위가 수행될 수도 있음


**3단계 - 최종 페이로드**

- 최종적으로 실제 악성 행위를 수행하는 프로그램 또는 코드가 실행
- RAT(Remote Access Trojan), 정보탈취 악성코드(Infostealer), 랜섬웨어, 백도어 등이 사용될 수 있음
- 최종 페이로드가 실행되면 정보 탈취, 원격 제어, 파일 암호화, 추가 악성코드 설치 등의 실질적인 악성 행위가 시작됨


# 악성 스크립트 분석 시 주요 확인 사항

1) **실행 주체 확인**
   - 어떤 프로세스가 스크립트를 실행했는지 확인
   - 부모 프로세스와 자식 프로세스 관계 분석
   - 예: Office 프로그램 → `cmd.exe` → PowerShell과 같은 비정상적인 프로세스 체인 확인

2) **스크립트 코드 및 난독화 분석**
   - Base64, 문자열 분할, 변수명 난독화 등 확인
   - 인코딩된 데이터가 실제로 어떤 명령이나 데이터를 포함하는지 분석
   - 난독화를 제거한 후 코드의 실행 흐름을 확인

3) **네트워크 행위 분석**
   - 외부 IP 또는 도메인과 통신하는지 확인
   - HTTP/HTTPS 등의 네트워크 연결 확인
   - 추가 페이로드를 다운로드하는 행위가 있는지 확인

4) **파일 및 프로세스 행위 분석**
   - 새로운 파일을 생성하거나 삭제하는지 확인
   - 추가 프로세스를 실행하는지 확인
   - 메모리에 악성 코드나 데이터를 로드하는지 확인

5) **지속성(Persistence) 확인**
   - 레지스트리 Run 키
   - 작업 스케줄러
   - 서비스
   - 시작 프로그램
   - WMI 등의 지속성 기법이 사용되었는지 확인

6) **최종 목적 확인**
   - 정보 탈취
   - 원격 제어
   - 권한 상승
   - 추가 악성코드 설치
   - 랜섬웨어 실행 등 공격자가 최종적으로 수행하려는 행위를 파악


# 악성 스크립트 분석의 핵심

악성 스크립트 분석에서는 스크립트의 문법만 분석하는 것이 아니라 "어떤 프로세스가 실행했으며, 어떤 명령을 수행하고, 무엇과 통신하며, 최종적으로 어떤 행위를 하는가"를 전체 실행 흐름으로 분석하는 것이 중요하다.

즉, 악성 스크립트 분석은 다음과 같은 흐름으로 접근할 수 있다.

**전달 파일 → 스크립트 실행 → 난독화 해제 → 프로세스 및 네트워크 행위 분석 → 지속성 확인 → 최종 페이로드 분석 → 공격 목적 파악**
